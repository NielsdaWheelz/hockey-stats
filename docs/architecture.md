# architecture and statistical design

one operator fits models locally and publishes a completed database. a browser can read that publication with the drive detached. this fixes the main boundary in the system. evidence and numerical work live upstream of publication. browsing uses accepted outputs and computes the comparisons the reader selects. ## how the estimates compose

- the four execution heads produce a joint distribution over five outcomes. a blocked attempt has a distribution of plausible origins. value is integrated over those origins. neutral execution sets the shooter, setter, goalie and joint coaching residuals to zero under the retained circumstances. actual outcomes, actor-conditioned expectations and reference-execution expectations have distinct meanings. [execution contract](specs/v1-06-execution-scoring.md)
- positive opportunity volume, normalized spatial shares and reference quality compose into a lineup's chance rate. the 5v5 and special-teams families use 656 cells and forty retained spatial modes. special teams share information across 5v4, 5v3 and 4v3 with distinct game-state baselines. retain the defined rink frame, cell area, support, units and sign when deriving maps and scalar summaries. [5v5](specs/v1-08-positive-attribution.md) · [special teams](specs/v1-09-special-teams.md)
- penalty hazards value team minor awards. shootiness assigns a share of opportunities among the skaters and enters execution accounting. territory estimates movement between recorded anchors and applies an explicit terminal-zone proxy to value successor starts. goalies have stopping and conditional post-save outcomes on matched populations. interpretation follows the observable event behind each estimate. [penalties/shootiness](specs/v1-10-penalties-shootiness.md) · [territory](specs/v1-11-territory-successor-value.md) · [goalies](specs/v1-07-goalie-continuation.md)
- the v1 skater headline is seasonal underlying level on 1,000 5v5, 100 power-play and 100 penalty-kill minutes. its ten terms use one league reference. the companion total uses the complete position-specific depth reference. actual usage and observed rates remain available. the common workload entails hypothetical deployment for specialists. [ledger](specs/v1-12-value-ledger.md) · [scientific interpretation](research/model-direction.md)
- for v2 dated ability, the numerical producer owns the retrospective curve, reference and exposure supporting each point. the publisher binds target date, evidence cutoff and model/input identity. the browser selects a published point and carries that identity into comparison and export. a dated total requires compatible dated components throughout. [temporal target](research/model-direction.md#retrospective-player-ability)

## change boundaries

**inputs.** original bytes and expensive fitted states have permanent locations and identities. reconstruction and source corrections change derived evidence. prepared features can be implemented, exercised and inactive. a recipe selects explicit families, cutoffs, missingness rules and reference conditions. a changed design needs a new fit before comparing its effect. the data owner records opportunities lost to missing evidence. [feature repertoire](model-features.md) · [fixture policy and examples](../fixtures/README.md)

**dated selections in v2.** the corpus writer owns completed-game membership and the digest of each selected game file. every consumer checks the bytes it reads. retain the exact inputs behind earlier selections when correcting a game. recompute dependent season totals, histories and cohorts for the affected season. [snapshot contract](issues/current-season-snapshot.md#dated-selection)

the publisher will compose three historical modeled seasons and current observed results into one admitted database. bind each season and method to the evidence it actually used. the delivered exchange and reader enforce one shared preparation digest, so carrying a historical fit forward requires preserving its own identity as new facts arrive. give the current season its own person catalog, supported factual rows and explicit dispositions for unfitted families. the application reads these dispositions to choose the default view and label cutoffs on page and export. [exchange contract in v1](../analysis/src/hockey_stats/analysis_publication.py#L2203) · [method binding](../app/src/server/analysis-publication.ts#L333) · [reader behavior](product-inventory.md#v2-current-season-views)

**selected teammate context in v2.** the typed context reader intersects two skaters' `dressed_game` rows on season, game and club, then groups the selected club's `interval_fact` rows by `interval_player` membership. the recorded and scored populations each carry their own mass and seconds. the existing focal together/apart selection keeps its focal-player game universe. the deployment list requests a reciprocal result only when the reader opens a pair. plot, table and csv share that result. [published facts](../analysis/src/hockey_stats/analysis_publication.py#L805) · [existing focal selection](../app/src/server/selected-publication.ts#L459) · [reader contract](product-inventory.md#v2-reciprocal-teammate-view)

**annual discovery and history in v2.** the compact publication reader supplies the requested scalars, their support and reference identities for each skater-season. discovery pairs fields by publication, season and player. history takes one field from each year's cohort. the application owns qualification, midranks and the shared nearest-rank quartile calculation. chart, table and exports consume the same result. opening a player's evidence requests detail separately. [field definitions](../app/src/web/analysis-values.ts#L338) · [discovery contract](product-inventory.md#v2-many-player-scatters) · [history contract](product-inventory.md#v2-annual-peer-context)

**publication.** native python and its locked environment own derivation, model fitting and export. effect, node and react own capture, reading and presentation. python writes the publication and typed node readers consume it. users browse published seasons and choose cohorts without launching a fit. exact semantic evidence belongs with a numerical output. the review proposes separating editable presentation wording from producer artifacts where they are still coupled. [application contract](specs/experimental-application.md) · [post-release review](research/v1-review.md)

**operation.** local commands take explicit inputs. expensive outputs remain on expansion with accepted manual rerun risk. a local serving pair contains everything the browser needs. switch deliberately, preserve one previous publication and use the runtime compatible with it for rollback. the verified cross-schema cutover and same-schema fixture rehearsal are documented separately. [operator guide](operations.md) · [locked operating and evidence roots](storage.md)

**verification.** source identities, supported time, chronology, finite probabilities and conserved value are correctness conditions. calibration, attribution, numerical sensitivity and player uncertainty require evidence for the specific claim. native study code owns the experimental policy and verdict. shared production modules own common arithmetic and readers. keep durable fixtures and only selected fast checks at stable boundaries. [verification policy](specs/07-lightweight-testing.md) · [frozen studies](research/README.md)
