# execution shift-start chronology

problem: upstream preparation can assign a faceoff shift start using a same-clock faceoff that follows the focal attempt. the saved shift fact does not itself imply that its faceoff anchor was available before that attempt. execution consumes the prepared shooter start type/zone without a separate focal chronology check.

impact: this creates a possible future-information path into execution predictors and the fixed neutral targets consumed downstream. no affected event in the accepted score population has been established by this review. the v1-08 spatial encoder now requires saved anchor chronology strictly before the focal event, but that repair neither changes nor certifies upstream fitted states or scores.

evidence: [feature_data.py](../../analysis/src/hockey_stats/feature_data.py) builds same-clock faceoff candidates in `_deployment` without a focal-order cutoff. [analysis_context.py](../../analysis/src/hockey_stats/analysis_context.py) copies the coherent shift's start type/zone into prepared event deployment facts. [execution_design.py](../../analysis/src/hockey_stats/execution_design.py) consumes those shooter deployment fields. a synthetic spatial counterexample with focal order 10 and anchor order 11 reproduced the mechanism; source indices were deliberately reversed. the earlier seven-game fixture screen compared source indices and clocks, so its zero witnesses do not establish chronology eligibility across the accepted execution population.

resolution: inspect the relevant saved anchor/focal chronology and prepared shooter deployment on explicitly selected accepted inputs. either establish that no affected execution predictor occurs in that declared population, or locate affected keys and obtain assignment for the responsible upstream repair and any necessary replacement fits/scores. preserve existing accepted artifacts and scientific verdicts. no acquisition, preparation, refit or rescore is assigned by this issue.
