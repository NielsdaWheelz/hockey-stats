# legacy fixture fidelity

status: open before fixture admission. observed 2026-09-29 at legacy commit `1d45312ed4a2d797150e377c87ecdba231b5ebfc`.

## problem and impact

the old manifest assigns `Live` at game level even though several files are transformed. synthetic legacy html matches an idealized decoder contract. expected snapshots are generated by the implementation under test. these are useful regression artifacts but insufficient evidence of current upstream compatibility or independent correctness.

## evidence and reproduction

- [fixture readme](https://github.com/NielsdaWheelz/hockey-stats-legacy/blob/1d45312ed4a2d797150e377c87ecdba231b5ebfc/packages/core/fixtures/README.md) documents projected boxscores, filtered/augmented rosters, filtered reference tables, and synthetic html.
- [capture entrypoint](https://github.com/NielsdaWheelz/hockey-stats-legacy/blob/1d45312ed4a2d797150e377c87ecdba231b5ebfc/packages/core/src/testing/live-capture/entrypoint-capture-fixtures.ts) implements those transformations and generated expectations.
- `manifest.json` lists 11 curated games: one `Live`, ten `Synthetic`; a separate failure-injection game is also present. all 79 listed file hashes match the checked-in bytes. matching digests prove preservation, not semantic correctness.

## resolution evidence

define per-file origin and transformation metadata. preserve a few complete, untouched upstream game captures and selected independent expected totals/events. retain small synthetic cases for known boundaries, clearly labeled. test the actual upstream boundary before internal normalization. do not use generated expectations alone to establish correctness, or this small corpus to claim training quality or statistical calibration.

the old play-by-play and shift files are candidates for reuse after provenance review. no fixture has yet been admitted into the new project's test contract.
