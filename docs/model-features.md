# retained analytical feature repertoire

status: user choice approved 2026-10-08; prospective policy, not an implemented capability. [03k](specs/03k-feature-repertoire.md) owns preparation/selection work. [the input audit](research/model-input-audit.md) owns source-field and peer-method evidence; this page owns the feature-family inventory and retention policy. product features remain in [the capability inventory](product-inventory.md).

## policy and contract

implement and retain all distinct, defensibly computable feature families supported by the reviewed public-data scope, including families not selected by the current model. add newly identified families to this inventory and their preparation queue. build them in reviewable batches; do not defer every unused family until a fit requests it. available public sources requiring acquisition/admission remain explicit pending dependencies; inaccessible tracking is not available evidence.

retain correct extraction/encoding after an adverse experiment. a model recipe selects named families independently for each stage; omission disables use, not the supported implementation. remove incorrect derivations, duplicate implementations, obsolete schemas and superseded estimators. this does not restore legacy code or compatibility paths.

each family declares source paths/derivation, observed/derived/imputed meaning, units/frame, analytical clock/lookback and information availability, missing/conflicting/not-applicable behavior, permitted stages, reference treatment and code owner. focal labels and later evidence are not ordinary predictors. derived possession, speed, setters and releases must retain their proxy/inference meaning.

use ordinary python functions and explicit per-stage lists. fitted artifacts identify selected families, exact feature names/order, transformations and source/preparation identity. reuse current feature constructors; separate fixed `π` from extended `u` encoding. no feature service, registry, expression language or automatic interaction generator. named interactions can be retained too; enumerate reviewed ones rather than every possible cross-product.

fit learned scaling, bins, category selection and imputation parameters only on the recipe's declared training evidence; save them with the fitted design. later records may supply permitted reconstruction evidence when applying a fixed imputer, not change its fitted parameters. deterministic extraction still obeys its declared retrospective/predictive information boundary.

ablation means refitting without a family under a declared comparable population/protocol. zeroing fitted coefficients is a separate perturbation. unused families must not change baseline eligibility; selected families' unavailable evidence cannot silently become zero or discard rows. expensive construction can follow selection without deleting its implementation.

## initial family inventory

current status describes implemented subsets, not readiness of every listed field. 03k's full spec traces exact fields/functions and names each queued batch; new source families require explicit admission before use.

complete passing/screens, tracked entries/exits, trajectories and representative physical block release/contact pairs remain unavailable in the admitted public corpus. catalogue possible enrichment; never synthesize it as observed input. unsupported proxies remain pending until their meaning can be specified. optional paid evidence stays separate from the core.

preparation breadth does not expand the first analytical population, activate every feature, prescribe an all-features fit or authorize automatic ablation campaigns. tradeoff accepted by the user: more maintained code, schema and verification work before demonstrated predictive value, in exchange for a reusable research repertoire. empirical model selection and player-component accounting remain separate.
