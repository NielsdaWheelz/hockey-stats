## observation contract

`interpret_game` owns game-source observations; `interpret_references` owns season-filtered bio observations. source rows add `source_fields={values,problems,evidence}`. `values` retains the exact selected source names, including nulls and original formatted strings. each null has one matching `problems[field]={status,reason,evidence_refs}`; zero and false stay values. evidence entries name `source,path,input_index`, linking the document's `inputs` receipt and body digest. conflict never licenses selecting another person's observation. source-specific partial fields survive independently.

the changed contracts are interpretation/envelope 4 and reference 2. root owns corpus/selection 2 and strict consumer validation. raw receipts and inventory rows remain unchanged. no source acquisition, old reader, coefficient adaptation or rewritten historical result is part of this cutover.

report/source retrieval time is observation provenance. bio `requested_season` identifies the report filter; `requested_at` identifies retrieval; `effective_at=null` states that no historical effective date was captured. historical game dates, source retrieval dates and analytical cutoffs are different concepts.

## ownership and interfaces

`feature_data.prepare_game(envelope, attempts, *, input_ref, bio_rows, chronology)` returns `{game_facts,player_game_facts,history_summary}` and adds each attempt's `feature_facts`. `chronology={ordered,order_supported,scores}` comes from the existing score/order preparation once; there is no second raw parser, reconstruction or chronology validator. `bio_rows` are the corpus's attributed join rows, including observation locators/retrieval times.

`feature_history.prepare_history(inventory_rows, summaries, target_game_ids)` returns keyed game/team and player pregame groups. inventories include each declared history game even when its summary is unavailable. history adds no target attempts. game summaries retain compact per-counter evidence/coverage and participation, not bulky source documents.

`feature_data.prepare_missing_game(entry, *, input_ref)` retains the target's inventory game/team/date facts and explicitly unavailable recording/component/people groups; it returns no invented player rows. missing or identity-unavailable target games still have their shared game key. history summaries are computed once per admitted game, then rolling/date-prefix aggregates answer shared pregame queries; no prior-game scans occur per attempt.

every fact group is `{values,problems,evidence}`. every null scalar has a field problem `{status,reason,evidence_refs}`; status is `unavailable`, `conflict` or `not_applicable`. known false/zero survive. nested player, unit and window groups use this same envelope. evidence refs index that envelope's evidence list; evidence carries source/input identity and exact interpreted/report/shift/interval/bio locators. no unknown-category/missingness predictor is prepared.

## exact shared fields and history windows

`feature_player_games[game_id][str(player_id)]` has `people`, `workload`, `calendar_rest`, and `history`; this key requires a unique consistent roster/boxscore identity. people values include `player_id,team_id,reported_position,first_name,last_name,name,birth_date,shoots_catches,age_days,bio_observations,reported_totals`. age is `(game_date-birth_date).days`; negative/missing/conflicting ages are unavailable. bio report `source_fields` retain exact source names and requested season/receipt/retrieval dating; current totals/body/team/hand are observations, not historical snapshots. `reported_hand_stable_trait` explicitly licenses only the declared hand transform.

`workload[previous_game|days_7|days_14|season_prefix]` and `history[prior_season_1|prior_season_2]` are window envelopes with `scope,start,cutoff,complete,contributing_game_ids,unavailable_game_ids` and exact counters `ice_appearances,starts,relief_appearances,toi_all_seconds,toi_5v5_seconds,shifts,attempts,goals,sog,saves,shots_against,goals_against`, each with its own problem and `known_<counter>` partial sum. `complete` summarizes all applicable counters, never overrides per-counter completeness. non-goalie starts/relief/goaltending counters are not applicable rather than zero.

`calendar_rest.values` has `prior_appearance_exists,prior_game_date,calendar_gap_days,prior_one_date,prior_two_date,games_days_7,games_days_14`; player game counts count positive-toi appearances. `feature_games[game_id].teams[str(team_id)].calendar_rest` uses `prior_game_exists` for inventory game presence and team calendar windows. team schedule counts may be complete despite missing captured games; player counters cannot.

`history` additionally retains first observed appearance, first-observation left-censoring, prior team/role observations and changes. first local appearance never becomes career debut. fitted effects require a separate dated compatible producer and remain external.

windows are current regular-season `[D-7,D)`, `[D-14,D)`, season prefix `<D`, and each of two complete preceding regular seasons. calculate every date's target snapshots BEFORE accumulating any games that date. id, scheduled time and source array cannot order same-day games. previous player game is previous positive-toi appearance; previous team game is previous earlier inventory date. missing relevant evidence that could change that predecessor makes it unavailable.

positive reported toi proves participation; unused backup/roster inclusion does not. complete attributed roster/boxscore coverage can prove nonparticipation. unknown or ambiguous roster/boxscore membership can conceal the player's presence, so absence, zero appearance and predecessor cannot be asserted. individual available counters survive defects in another field. an incomplete total is null even when its known partial sum is 0. empty history inventories mean unavailable history, not invented opening-season zero.
