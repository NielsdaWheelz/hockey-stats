## observation contract

`interpret_game` owns game-source observations; `interpret_references` owns season-filtered bio observations. source rows add `source_fields={values,problems,evidence}`. `values` retains the exact selected source names, including nulls and original formatted strings. each null has one matching `problems[field]={status,reason,evidence_refs}`; zero and false stay values. evidence entries name `field,source,path,input_index`, linking each exact value to the document's `inputs` receipt and body digest. raw source-field envelopes have one locator for each named field; goalie strength-derived envelopes have pair/goals locators, two carrying the same exact derived field name. null problems name exactly their own field's locator indices. association is independent of json object/evidence order; it does not infer a field from an html alias or source-path suffix. conflict never licenses selecting another person's observation. source-specific partial fields survive independently.

the changed contracts are interpretation/envelope 4 and reference 2. `corpus.py` and `chance_data.py` own corpus/selection 2 and strict consumer validation. raw receipts and inventory rows remain unchanged. no source acquisition, old reader, coefficient adaptation or rewritten historical result is part of this cutover.

report/source retrieval time is observation provenance. bio `requested_season` identifies the report filter; `requested_at` identifies retrieval; `effective_at=null` states that no historical effective date was captured. historical game dates, source retrieval dates and analytical cutoffs are different concepts.
