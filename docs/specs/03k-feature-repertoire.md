# pr03k — retained feature preparation and selection

status: **approved direction, proposal stub; full specification/assignment required. implementation, acquisition and real-corpus fitting not authorized.** separate from [03j](03j-chance-experiment.md), which consumes saved predictions. [feature policy/inventory](../model-features.md)

target: implement the reviewed, source-backed analytical families and retain correct implementations regardless of current recipe inclusion. begin with admitted captures/references and reconstructed facts; extend interpretation where required facts still exist only raw. build reviewable batches with a recorded completion queue, rather than quietly omitting families without immediate predictive demand. preparation is useful capability, not admission of a model.

## ownership and capability

- source interpretation/reference modules own attributed facts, joins, units and unavailable/conflict states. the full spec identifies any genuinely additional source; acquisition is a separately explicit prerequisite, not a runtime fallback.
- feature preparation owns reusable geometry, game/preceding-event, continuity, shift/deployment/rest, people/history and recording families from the inventory. retain outcome labels and observed/component facts separately from predictor eligibility. later components own their targets and statistical use; this does not fit goalie, special-teams or attribution models.
- numerical stage designs own explicit selected families, encodings/penalties, order and reference treatment. extending avoidance cannot extend a frozen origin design implicitly. distinguish supported inference from observations and reject invalid stage combinations.
- use existing `interpret.py`, `references.py`, reconstruction and `chance_data.py` primitives; separate reusable pure construction from `chance.py`'s numerical layouts where it absorbs complexity. no generic feature framework or one module per scalar.

## acceptance and full-spec decisions

the full spec names the first non-overlapping batch, exact fields/derivations, current/queued family status, source/cutoff/continuity contracts, selected-family interface and affected artifact revision. learned transformation/imputation parameters use declared training evidence and are saved with the design. absent physical tracking cannot become a computed observation. unavailable, conflict and not applicable remain distinguishable; unused features cannot alter baseline rows.

verify hand-checked ordinary/broken captures, history and clock boundaries, feature selection and exact unchanged-design reproduction through temporary integration checks. selecting a family produces its declared deterministic design; excluding it retains the implementation and original evidence. preserve fixture facts, refactor/reverify, then delete temporary tests/dependencies. no real fit campaign is part of preparation; small fixture numerical checks may verify integration.

verification records completed and outstanding batches/source dependencies against the inventory. completing a bounded first batch does not complete the reviewed repertoire; keep its remaining preparation queue explicit.

correct inactive feature code stays; consolidate duplication and hard-cut superseded derived contracts without legacy readers. invalidate reuse when changed semantics/order make a saved fit incompatible; execute historical implementations explicitly for historical comparisons rather than silently adapting old fits. preserve expensive artifacts.

after this slice, native experiments can select or ablate supported families without rewriting extraction. ablation still requires refitting and a fixed comparison. this slice neither chooses the next model nor supplies a 04 handoff. cost: broad preparation/maintenance before predictive value is demonstrated; no added service, scheduler or permanent testing harness.
